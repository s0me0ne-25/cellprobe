Терминология — по `claude/GLOSSARY.md`.
Репозиторий: https://github.com/s0me0ne-25/cellprobe · Лицензия: GPLv3

## 0. Назначение

Cellprobe — Android-приложение для фонового мониторинга режима работы враждебных сетевых фильтров (ТСПУ, белые списки мобильных операторов, точечные блокировки прокси). Оно периодически проверяет доступность нескольких наборов ресурсов, по результату определяет текущий режим сети и рекомендует пользователю подходящее средство разблокировки. По нажатию на уведомление запускается заранее выбранное приложение: VPN-клиент, клиент olcRTC, клиент I2P или браузер с ЛК провайдера.

Наличие TUN-интерфейса само по себе ничего не означает. Если пользователь работает через TUN, он обязан добавить Cellprobe в исключения своего VPN-клиента. Идёт ли трафик Cellprobe через VPN, приложение не определяет и не показывает: пользователь предупреждён, дальше Cellprobe работает только с тем, что наблюдает сам при проверках (ответивший список 4 даёт `LEAK`).

## 1. Платформа и распространение

| Параметр | Значение |

| minSdk | 24 (Android 7.0), охват ≈99,1% по данным Google на 01.12.2025 |

### 1.1. Совместимость 24–25 (через AndroidX Compat)

- Уведомления: на 26+ каналы, на 24–25 приоритет и звук задаются в каждом уведомлении. Код единый через `NotificationCompat`. На 24–25 в приложении есть переключатели звука и вибрации для каждого типа уведомлений вместо системных настроек каналов.
- Запуск foreground service: `ContextCompat.startForegroundService`.
- Состояние мобильных данных: `TelephonyManager.isDataEnabled()` на 26+, на 24–25 — `Settings.Global "mobile_data"`.
- Переход в настройки уведомлений: на 26+ официальный intent, на 24–25 — запасной вариант.
- Иконка: адаптивная плюс растровая для старых версий.
- `java.time`: через core library desugaring.
- `IME_FLAG_NO_PERSONALIZED_LEARNING` выставляется всегда, учитывает ли его клавиатура — на её усмотрение.
- Кнопки «Добавить виджет» (`requestPinAppWidget`) на 24–25 нет, показывается подсказка добавить виджет вручную.

### 1.2. Распространение

- **F-Droid + GitHub Releases.** Google Play не используется.
- Две сборки:
  - `fdroid` — без самообновления и без `REQUEST_INSTALL_PACKAGES`;
  - `github` — с самообновлением (начиная с альфы).
- **MVP:** только релизы на GitHub, без самообновления и без Obtainium.
- **Альфа:** самообновление из GitHub Releases. Проверка через GitHub API, скачивание APK, сверка SHA-256, установка через `PackageInstaller`. Совпадение подписи Android проверяет сам.
- **Воспроизводимые сборки**, чтобы F-Droid публиковал APK с подписью разработчика. Тогда пользователь может переходить между каналами без удаления приложения.
- **Ключ подписи** генерируется до первого релиза и хранится офлайн. Подписываем им с первого релиза на GitHub. В CI ключ не попадает. Смена ключа = переустановка приложения у всех пользователей.
- **Никаких зависимостей от GMS:** ни Play Services, ни Firebase, ни Play Integrity.
- **Верификация разработчиков Google.** Глобально вводится в 2027 году. Разработчик не верифицируется (это требует деанона). В README описывается одноразовый «расширенный режим» (advanced flow) установки неверифицированных приложений.

### 1.3. На вырост: Google

Сейчас не реализуется. Архитектура не должна закрывать этот путь.

- **Верификация разработчика** (если появится верифицированный аккаунт — свой, коллеги или организации). Регистрируются имя пакета и SHA-256 отпечатки ключей. Ключей может быть несколько: наш и, если F-Droid переподписывает, ключ F-Droid. При больше чем 50 установках владение подтверждается файлом `assets/adi-registration.properties` с фрагментом из консоли в очередном релизе. Приватный ключ никому не передаётся.
- **Сборка `play`** (если когда-нибудь будет):
  - без самообновления и без `REQUEST_INSTALL_PACKAGES`;
  - вместо прямого запроса исключения из оптимизации батареи — переход к общему списку настроек батареи;
  - свой способ фонового выполнения без постоянного FGS `specialUse` (§8.1);
  - страница с политикой конфиденциальности.

  Подпись через Play App Signing: либо загружаем в Google наш ключ (подпись одна на все каналы, но копия ключа у Google), либо ключ Google (переход между каналами только через переустановку).
- **Что соблюдаем уже сейчас:**
  - ключ подписи хранится обычным экспортируемым файлом keystore;
  - код, зависящий от канала, живёт только в flavor-модулях;
  - движок проверок не зависит от времени жизни сервиса (§8.1);
  - минимум опасных разрешений.

## 2. Списки проверяемых ресурсов

Для всех списков действует **OR-логика**: список считается доступным, если ответил хотя бы один его ресурс.

| Список | Назначение | Пресет | Может быть пустым | «Сброс на пресет» |
|---|---|---|---|---|
| 1 | Никогда не блокируются, проверка связи как таковой | `https://ya.ru`, `https://mail.ru`, `https://vk.com`, `https://max.ru`, `https://avito.ru` | нет | да |
| 2 | Блокируются только в режиме белых списков | `https://google.com`, `https://apple.com`, `https://microsoft.com` | нет | да |
| 3 | Личные VLESS/Reality-входы пользователя | — | да | нет |
| 4 | Заведомо заблокированные | `https://youtube.com`, `https://meduza.io`, `https://instagram.com` | нет | да |
| ЛК | Личные кабинеты провайдеров (оператор, домашний провайдер) | — | да | нет |

### 2.1. Правила редактирования

- В любом списке можно удалить любую запись. Списки 1, 2 и 4 нельзя **сохранить** пустыми.
- «Сброс на пресет» восстанавливает записи пресета.
- **Автообновление пресетов.** Пока пользователь ни разу не менял список, он следует пресету текущей версии приложения. После первой правки (флаг `customized`) список больше не трогается.
- У каждой записи списков 1, 2, 4 и ЛК может быть необязательный маркер-подстрока для проверки содержимого — его задаёт пользователь для своих записей. **У пресетов маркеров нет:** для HTTPS валидный сертификат уже доказывает, что ответил настоящий сайт, а маркер легко даёт ложный `CONTENT_MISMATCH` (капча, антибот, редирект без тела).
- **Строка записи** в редакторе: `domain.tld [✏️ редактировать] [❌ удалить]`. В списке 1 и ЛК есть ещё третья кнопка `[👮]` — сертификаты Минцифры для этой записи (§2.3). Иконки — эмодзи Unicode из системного шрифта (✏️ U+270F, ❌ U+274C, 👮 U+1F46E, 🚫 U+1F6AB), без библиотек иконок и без EmojiCompat. Все они есть уже в Unicode 6 и отображаются на API 24. Выключенное состояние — 🚫 поверх 👮 (два `Text` в одном `Box`). У каждой кнопки своё описание для экранного диктора, без него TalkBack зачитает название эмодзи («полицейский»).

### 2.2. Список 3: санитизация VLESS

- **Ссылка разбирается до того, как текст попадёт в поле ввода.** Это касается любого способа ввода: вставка из меню, буфер клавиатуры, набор. Изменение с `://` откатывается целиком, и в поле попадает только результат разбора. Сырая ссылка не оказывается ни в состоянии поля, ни в сохранённом состоянии экрана, ни в хранилище. Если вставить ссылку в поле названия, она обрабатывается так же.
- **Сохраняются только:**
  - `host` (IP или домен) и `port` (по умолчанию 443), IPv6 в квадратных скобках поддерживается;
  - `sni` (синонимы в ссылках: `peer`, `servername`); если его нет, а хост — домен, SNI = хост;
  - `fp` — отпечаток uTLS, не секретный, нужен для будущей проверки через uTLS; неизвестное значение отбрасывается;
  - название из `#fragment`: URL-декодированное, `+` читается как пробел (так кодируют v2rayNG и другие), без управляющих символов, до 64 символов. Редактируется.
- **Отбрасываются:** UUID, `pbk`, `sid`, `spx`, `flow`, `serviceName` и прочие параметры.
- **Ручной ввод — одной строкой** `host:port sni [fp]`, для доменного хоста SNI можно опустить. В этом же виде запись показывается при редактировании.
- **Принимаются строго ссылки с `security=reality` или `security=tls`** (регистр не важен). Отсутствие параметра, `none`, устаревший `xtls` (удалён в Xray 1.8) и любое другое значение — ошибка «Поддерживаются только протоколы безопасности tls и reality». Сам режим в записи не хранится: проверка у обоих одинаковая (§5.2).
- **Отклоняется с понятной ошибкой также:**
  - UDP-транспорты (`type=kcp`, `quic`);
  - ссылки других схем (trojan, ss, vmess, hysteria2 …) — поддержка позже;
  - несколько ссылок за раз;
  - IP-хост без SNI, SNI в виде IP.
- **Дубликат** — запись с тем же `host`, `port` и `sni`; название и отпечаток в сравнении не участвуют.
- **Если вместо IP домен**, он хранится как есть и резолвится при каждой проверке. Ошибка DNS — отдельный код результата.
- **Где сырая ссылка не должна осесть:**
  - не логируется и не сохраняется;
  - поля диалога: `TYPE_TEXT_FLAG_NO_SUGGESTIONS` + `IME_FLAG_NO_PERSONALIZED_LEARNING` (через перехват запуска клавиатуры в Compose);
  - название и адреса не показываются на заблокированном экране.

### 2.3. Сертификаты Минцифры (для отдельной записи)

- **Где доступно:** только в записях списка 1 и списка ЛК. В списках 2, 3 и 4 кнопки нет.
- **Кнопка `[👮]`:**
  - по умолчанию выключена — иконка перечёркнута оверлеем 🚫;
  - нажатие включает доверие к сертификатам Минцифры **только для этой записи**, перед включением — диалог с предупреждением «Включайте только при крайней необходимости»;
  - кнопка всегда нажимаема, но подсвечивается, если последняя проверка этой записи дала `CERT_RU_CA`;
  - при редактировании записи (✏️) флаг сбрасывается в «выключено».
- **Флаг хранится в записи** (`allowRuCa`). Его переключение не считается правкой списка, то есть не снимает автообновление пресета. При автообновлении флаг сохраняется для записей с тем же хостом. «Сброс на пресет» выключает все флаги.
- **Источник сертификатов:** официальная страница gosuslugi.ru/crt, файлы на `gu-st.ru` (`russian_trusted_root_ca_pem.crt`, `russian_trusted_sub_ca_pem.crt`). Только RSA-иерархия: ГОСТ BoringSSL не поддерживает.
- **Загрузка:** при первом включении флага у любой записи. Если включённых флагов не осталось, сертификаты удаляются.
- **Проверка загруженного:**
  - SHA-256 отпечаток корня зашит в код; при реализации сверяется по нескольким независимым источникам;
  - промежуточный сертификат принимается, только если он подписан этим корнем;
  - отпечаток не совпал → сертификат отвергается, в UI ошибка.
- **Запасной путь:** если ссылки на `gu-st.ru` перестанут работать, пользователь сам выбирает скачанный `.crt` через системный выбор файлов. Проверка по зашитому отпечатку та же.
- **Применение:** перед каждым запросом к записи с `allowRuCa` отдельным явным шагом строится `X509TrustManager`: системные корни + корень Минцифры. С ним создаётся отдельный клиент для этого запроса. Все остальные запросы идут через клиенты без него. Редиректы не проходим, поэтому доверие не утекает на другие хосты. Проверка имени хоста штатная.

## 3. Предварительная оценка состояния сети

Выполняется перед каждой проверкой по системным признакам, без сетевых запросов.

| Условие | Статус | Проверки ресурсов |
|---|---|---|
| Авиарежим или выключены мобильные данные, и нет Wi-Fi | `USER_OFFLINE` | не выполняются, ждём `NetworkCallback` |
| Активная сеть помечена флагом `NET_CAPABILITY_CAPTIVE_PORTAL` | `AUTH_REQUIRED` | не выполняются |
| Данные включены, нет сотовой сети | `NO_SIGNAL` | не выполняются |
| Данные включены, сеть есть, передача данных не поднимается (исключая роуминг с выключенными данными в роуминге) | `VOICE_ONLY` | не выполняются |
| Есть активная сеть с передачей данных (сотовая **или Wi-Fi**) | — | выполняются, см. §5 |

- **Системные признаки отслеживаются и во время проверки.** Если сеть пропала (авиарежим, все сети выключены, потеря покрытия) или появился флаг портала, запросы прерываются, а статус определяется по системным признакам — без ожидания таймаутов, которые дали бы ложный `NO_INTERNET`. Пропажа подтверждается повторным чтением через 2 с: при переключении сети (мобильная ↔ Wi-Fi) бывает миг совсем без сети. Признаки перечитываются и после того, как все запросы завершились: в авиарежиме они падают сразу, раньше, чем пропажа успевает подтвердиться. Результаты прерванных запросов отбрасываются, в журнале запись помечается «проверка прервана».
- **Wi-Fi проверяется наравне с сотовой сетью.** Типичные случаи: сельская местность, где интернет приходит по сотовой связи и раздаётся по Wi-Fi, и проводные провайдеры с разной степенью фильтрации. Тип сети показывается в статусе.
- **Тумблер «Отслеживать физическое пропадание сети»** (по умолчанию выключен). Подпись мелким шрифтом: «На рыбалке — вариант нормы, но в городе может указывать на шатдаун».
  - Выключен — `NO_SIGNAL` и `VOICE_ONLY` отображаются, но уведомлений не порождают.
  - Включён — участвуют в уведомлениях как статусы со строгостью 4.
- **`USER_OFFLINE`** — уведомлений нет. После восстановления связи — пауза 5–10 с, затем внеочередная проверка. Уведомление выдаётся, только если новый статус отличается от последнего объявленного до отключения.
- **Флаг портала** — сигнал системы, принимается без подтверждения. Когда флаг снимается, сразу запускается внеочередная проверка. Если пользователь отключил проверку портала (`captive_portal_mode 0`), срабатывает обычная лестница.
- **Две SIM-карты** — анализируется SIM, выбранная для мобильных данных.
- **`READ_PHONE_STATE` — только при крайней необходимости.** Основной путь обходится без него: слушатель состояния сотовой сети и состояние мобильных данных.
  - Если на конкретной версии Android без разрешения не обойтись, оно запрашивается только при включении тумблера «Отслеживать физическое пропадание сети», с экраном-объяснением.
  - Пользователь вправе отказать. Тогда работает менее точный запасной вариант определения `NO_SIGNAL` и `VOICE_ONLY`, без повторных запросов.
  - Почему так осторожно: системный диалог («совершать звонки и управлять ими») подрывает доверие, а на старых Android разрешение даёт доступ к IMEI и IMSI (до 10) и к номеру телефона (до 11).

## 4. Классификатор

Чистая функция в `:core`: `(предварительное состояние, результаты списков) → статус`. Берётся первое совпадение сверху вниз.

| Шаг | Условие | Статус | Название | Строгость | Цвет |
|---|---|---|---|---|---|
| 0 | флаг портала | `AUTH_REQUIRED` | Требуется авторизация | 3 | красный |
| 1 | ответил список 4 | `LEAK` | Свободный интернет | вне шкалы | зелёный |
| 2 | ответил список 3 | `NORMAL` | Стандартные блокировки | 0 | фиолетовый |
| 3 | ответил список 2 | `VLESS_BLOCKED` | VLESS заблокирован | 1 | жёлтый |
| 4 | ответил список 1 | `WHITELIST` | Белый список | 2 | красный |
| 5 | ответил хотя бы один ЛК | `PAY` | Оплатите связь | 3 | красный |
| 6 | ничего не ответило | `NO_INTERNET` | Полное отсутствие связности | 4 | красный |

Статус показывается названием (крупно) и пояснением (мельче). Полные тексты на обоих языках — в глоссарии. Фиолетовый — основной цвет темы, красный — цвет ошибки; жёлтый и зелёный подобраны отдельно для светлой и тёмной темы. `USER_OFFLINE` — обычным цветом текста.

### 4.1. Особые случаи

- Список 3 пуст и ответил список 2 → `NORMAL_NO_VLESS` (название как у `NORMAL`, пояснение — «Укажите ваши серверы VLESS…»), строгость 0, фиолетовый.
- ЛК пуст → шаг 5 пропускается.
- VLESS-вход, размещённый на IP из белого списка, может скрыть от проверки режим белого списка. Это осознанно: пока вход жив, VLESS как средство разблокировки доступен. Когда вход перестанет отвечать, сработает шаг 4.
- Состояние отдельных VLESS-серверов на классификацию не влияет. Оно показывается на главном экране и в журнале.
- Прочие статусы со строгостью: `NO_SIGNAL` и `VOICE_ONLY` — 4 (только при включённом тумблере). `USER_OFFLINE` вне шкалы и не уведомляется.

## 5. Сетевой слой проверок

### 5.1. Клиент (MVP)

- **OkHttp + Conscrypt** (BoringSSL) как TLS-провайдер. Даёт TLS 1.3 на всех версиях Android и одинаковое поведение на API 24–36.
- **Базовая имитация WebView:**
  - `User-Agent` из `WebSettings.getDefaultUserAgent(context)`, кэшируется и обновляется при обновлении пакета WebView;
  - заголовки `Accept`, `Accept-Language` (из локали системы), `sec-ch-ua`, `sec-ch-ua-mobile`, `sec-ch-ua-platform`, `sec-fetch-*`, согласованные с версией Chrome из UA;
  - `Accept-Encoding: gzip, deflate, br, zstd`, для `br` и `zstd` подключаются декодеры;
  - TLS 1.2–1.3, набор шифров в порядке как у Chrome, ALPN `h2, http/1.1`.
- **Ограничения имитации** (приняты): GREASE, перемешивание расширений, ALPS, сжатие сертификатов, постквантовый обмен ключами, параметры и порядок заголовков HTTP/2 не повторяются. Точного совпадения JA3/JA4 нет.
- **Conscrypt не ставится глобальным провайдером безопасности:** иначе он подменил бы и фабрику доверия платформы, и `network_security_config` перестал бы действовать. Рукопожатие идёт через `SSLContext` из Conscrypt, а сертификаты проверяет штатный менеджер доверия платформы.
- **Распаковку тела делаем сами.** Раз `Accept-Encoding` выставляем мы, прозрачная распаковка OkHttp отключается. gzip и deflate — через okio, br — `org.brotli:dec`, zstd — `zstd-kmp` (нативная библиотека, ~0,6–0,8 МБ на архитектуру; правило R8 своё, в библиотеке его нет).
- **Только напрямую:** `Proxy.NO_PROXY`, системный HTTP-прокси не используется.
- **Гигиена:** без пула соединений, без кэша, без повторов, каждый цикл с нуля.
- **Доверенные корни сертификатов:** системные + свои через `network_security_config` — ISRG Root X1/X2 (Let's Encrypt) и GTS Root R1/R3/R4 (Google) из набора Mozilla, отпечатки записаны в конфиге. Пользовательские CA не доверяются. Сертификат проверяется всегда. Корень Минцифры подключается только для отдельных записей (§2.3).
- **DNS:** системный резолвер.

### 5.2. Подмена SNI для списка 3

Запрос идёт на `https://<sni>:<port>/` через свой DNS-резолвер, который для этого хоста возвращает IP прокси (или результат резолва домена прокси). Заголовок `Host` — `<sni>` без порта.

Что отвечает сервер неавторизованному клиенту:
- **Reality** прозрачно проксирует соединение на `dest` — приходят сертификат и страница сайта-прикрытия;
- **TLS** (с Vision или без) отдаёт собственный сертификат сервера, а дальше — сайт-заглушку, если настроен fallback, или закрывает соединение, если нет.

**Правило для списка 3 — одно для обоих режимов:**
- **вход доступен, если TLS-рукопожатие завершилось и сертификат прошёл строгую проверку** — такую же, как для остальных списков (системные корни + свои из `network_security_config`; корень Минцифры для списка 3 не применяется);
- **самоподписанные сертификаты не поддерживаются**, в том числе self-steal на самоподписе у Reality: такой вход получает `CERT_INVALID` и считается недоступным. Для своего домена есть Let's Encrypt;
- HTTP после рукопожатия — по возможности (набор объёма ниже); закрытое сервером соединение сразу после рукопожатия (TLS без fallback) даёт `OK_UNVERIFIED`.

**Редиректы (только для списка 3):**
- проходим только редиректы на тот же хост (совпадает с `sni`), тот же порт и только `https`, не больше 5 переходов;
- редирект на другой хост **не проходим**: запрос ушёл бы обычным DNS на настоящий сервер мимо прокси и дал бы ложный `OK`.

**Набор объёма для проверки обрыва — best-effort:**
- все запросы к одному VLESS-входу идут в одном TLS-соединении (keep-alive или HTTP/2), потому что порог обрыва ТСПУ, по наблюдениям, считается на соединение. Если сервер закрыл соединение, второе не открывается: набор объёма на этом заканчивается;
- полученные байты считаются на уровне сокета, вместе с TLS-рукопожатием и заголовками, — то же, что видит ТСПУ;
- `GET /` с переходами по редиректам того же хоста; если итоговый ответ закончился раньше 32 КБ — повторные `GET` итогового адреса в том же соединении, не больше 8 повторов. Вся проверка входа, включая подключение, укладывается в 10 с;
- набрать 32 КБ не удалось, но соединение ни разу не встало — вход считается работающим (`OK_UNVERIFIED`);
- после рукопожатия обрывом (`STALLED`) считается только остановка данных дольше таймаута чтения (5 с). Сброс или закрытие соединения сервером, ответ не по HTTP — `OK_UNVERIFIED`: так ведёт себя и TLS-вход без fallback.

### 5.3. Критерий «ресурс ответил»

- **Списки 1, 2, 4, ЛК:** валидная цепочка сертификатов + любой HTTP-ответ, включая 3xx и 4xx. Редиректы не проходим.
- Если задан маркер — подстрока должна найтись в первых 8 КБ распакованного тела, без учёта регистра. Кодировка текста — из `Content-Type`, затем из `<meta charset>`, иначе UTF-8.
- Ручная проверка («Проверить сейчас») всегда читает начало тела и показывает `<title>` страницы — чтобы было видно, что именно ответило.
- **Список 3** (процедура — §5.2):

  | Что произошло | Код | Для классификатора |
  |---|---|---|
  | Набрано ≥ 32 КБ | `OK` | доступен |
  | Данные пошли и встали (больше 5 с без данных) | `STALLED` | недоступен (характерный приём ТСПУ — обрыв после ~16–20 КБ) |
  | Рукопожатие с валидным сертификатом прошло, но 32 КБ набрать не удалось (маленькая страница, редирект на другой хост, сервер закрыл или сбросил соединение, кончилось время) | `OK_UNVERIFIED` | доступен; в диагностике и журнале пометка «обрыв не проверен» |
  | Рукопожатие не завершилось | `TCP_*` / `TLS_FAIL` | недоступен |
  | Сертификат не прошёл проверку (самоподписанный, не совпадает с SNI, истёк) | `CERT_INVALID` | недоступен |

### 5.4. Коды результата

`OK`, `OK_UNVERIFIED` (только список 3), `DNS_FAIL`, `TCP_TIMEOUT`, `TCP_RESET`, `TLS_FAIL`, `CERT_INVALID`, `CERT_RU_CA`, `HTTP_ERROR`, `STALLED`, `CONTENT_MISMATCH`, `SKIPPED` (не проверялся: в списке уже ответил другой ресурс).

Код ошибки определяется по фазе соединения, в которой она случилась:

| Фаза | Ошибка | Код |
|---|---|---|
| любая | имя не разрешилось | `DNS_FAIL` |
| любая | сертификат не доверен, истёк, не совпадает с хостом | `CERT_INVALID` |
| TCP-подключение | таймаут / отказ или сброс | `TCP_TIMEOUT` / `TCP_RESET` |
| TLS-рукопожатие | любая другая (сброс, таймаут, протокол) — типичная картина фильтрации по SNI | `TLS_FAIL` |
| ожидание заголовков ответа | любая | `HTTP_ERROR` |
| чтение тела | таймаут или сброс сокета / прочее (битое сжатие и т. п.) | `STALLED` / `HTTP_ERROR` |

`CERT_RU_CA` — цепочка выдана иерархией «Russian Trusted …», а у записи доверие к Минцифры выключено. Запись подсвечивается в редакторе, на главном экране — подсказка.

Классификатор смотрит только на «доступен / нет»: доступны `OK` и `OK_UNVERIFIED`. Подробный код пишется в журнал и пригодится будущим эвристикам.

### 5.5. Порядок опроса

- Все списки опрашиваются параллельно.
- Внутри списков 1, 2 и 4 первый ответивший ресурс отменяет остальные запросы.
- VLESS-входы опрашиваются все: состояние каждого показывается на главном экране и в журнале (§4.1, §9.1).
- ЛК опрашиваются все, чтобы отметить каждый ответивший.
- Если весь список не ответил, перед вердиктом он один раз перепроверяется.
- Таймауты: подключение 5 с, чтение 5 с, весь запрос 10 с. Цикл укладывается примерно в 10–15 с.

### 5.6. Трафик

Счётчик трафика проверок (за сутки и за месяц, по местному времени) отображается в UI. Источник — системный счётчик трафика приложения (`TrafficStats` по UID, тот же, что у системного экрана «Передача данных»): Cellprobe других запросов не делает, поэтому разница до и после проверки — трафик этой проверки.

## 6. Стабилизатор (антиспам)

Чистый конечный автомат в `:core`. Работает с тремя статусами:
- **наблюдённый** — результат одного цикла;
- **подтверждённый** — то, что показываем в UI, уведомлении сервиса и виджете;
- **объявленный** — последний статус, о котором было уведомление о переходе.

### 6.1. А — подтверждение

- Если наблюдённый статус отличается от подтверждённого, он становится кандидатом, и через 15 с запускается внеочередная перепроверка.
  - Перепроверка дала тот же статус → кандидат подтверждается.
  - Вернулся прежний статус → кандидат отбрасывается.
  - Третий статус → новый кандидат и ещё одна перепроверка. Не больше трёх подряд, затем принимается самый строгий из увиденных.
- `AUTH_REQUIRED` и `USER_OFFLINE` принимаются сразу.

### 6.2. Б — «мигание»

- ≥4 подтверждённых перехода за скользящие 30 минут → метастатус `UNSTABLE`:
  - одно громкое уведомление «Сеть нестабильна: переключается между X и Y»;
  - дальше это уведомление только тихо обновляется;
  - нажатие открывает приложение для самого строгого статуса из окна.
- Статус не менялся 15 минут → выход из `UNSTABLE`, обычное уведомление «Сеть стабилизировалась: <статус>».
- При смене типа сети (Wi-Fi ↔ мобильная) счётчик сбрасывается.

### 6.3. В — громкость (вне `UNSTABLE`)

| Новый подтверждённый по сравнению с объявленным | Громкое было < 10 мин назад | Уведомление |
|---|---|---|
| такой же | — | нет |
| строже | нет | громкое |
| строже | да | обычное |
| мягче | — | обычное |

- Переход, вызванный сменой типа сети (Wi-Fi ↔ мобильная), — обычное уведомление в любую сторону.
- `LEAK`: одно громкое уведомление, затем тихое, пока ситуация не исправится.
- Все пороги (15 с; 4 перехода / 30 мин; 15 мин; 10 мин) — внутренние константы. Позже возможна одна настройка «Чувствительность» с тремя положениями.

## 7. Уведомления

### 7.1. Каналы (на 26+)

- «Ужесточение» — `IMPORTANCE_HIGH`;
- «Смягчение» — `IMPORTANCE_DEFAULT`;
- «Сервис» — `IMPORTANCE_MIN`.

На 24–25 те же уровни задаются приоритетом каждого уведомления, а звук и вибрация — переключателями внутри приложения.

### 7.2. Общие правила

- **Уведомление сервиса** (обязательное для foreground service) показывает текущий подтверждённый статус, тип сети и время последней проверки.
- **Уведомления о переходах** выводятся под одним ID и заменяют друг друга (`setOnlyAlertOnce` при тихих обновлениях).
- **На заблокированном экране** — только статус, без адресов и меток.

### 7.3. Действие по нажатию

| Статус | Нажатие | Кнопки |
|---|---|---|
| `LEAK` | VPN-клиент | — |
| `NORMAL`, `NORMAL_NO_VLESS` | VPN-клиент | — |
| `VLESS_BLOCKED` | клиент I2P | «I2P», «VPN-клиент» |
| `WHITELIST` | клиент olcRTC | — |
| `PAY` | окно Cellprobe со списком ЛК | до 3 кнопок с доменами ЛК |
| `AUTH_REQUIRED` | настройки Wi-Fi (на мобильной сети — настройки мобильной сети) | — |
| `NO_INTERNET`, `NO_SIGNAL`, `VOICE_ONLY` | на Wi-Fi — настройки Wi-Fi, на мобильной сети — настройки мобильной сети | — |
| `UNSTABLE` | приложение для самого строгого статуса из окна | — |

Если для роли не выбрано приложение, нажатие открывает Cellprobe на соответствующей настройке.

Приложения запускаются через `getLaunchIntentForPackage`. Видимость пакетов обеспечивается `<queries>` для `MAIN/LAUNCHER`, без `QUERY_ALL_PACKAGES`.

### 7.4. Уведомление «Оплатите связь»

- **Тело** (`InboxStyle`) — все ЛК, сокращённые до хоста. Схема, путь и параметры отбрасываются, из хоста убирается только `www.`. Если у двух записей одинаковый хост, дописывается первый сегмент пути. Ответившие помечены галочкой, порядок не меняется.
- **Кнопки:** если ЛК не больше трёх, у каждого своя кнопка. Нажатие → `ACTION_VIEW` с полным URL: откроется браузер по умолчанию или системный выбор.
- **Нажатие на само уведомление** открывает небольшое окно Cellprobe поверх текущего экрана с полным списком ЛК и теми же отметками.

## 8. Фоновое выполнение

- **Foreground service** с типом `specialUse` (на 34+). `dataSync` не используется из-за лимита на Android 15+. WorkManager не используется: минимальный интервал 15 минут.
- **Расписание:** `setExactAndAllowWhileIdle` (на 31+ нужно разрешение «Будильники и напоминания»). Если разрешения нет — неточные будильники с честной пометкой в UI. На время цикла проверки берётся partial wakelock.
- **Исключение из оптимизации батареи** — прямой системный запрос (ограничений Play на нас нет).
- **Интервал:** настраивается от 30 с до 60 мин, отдельно для включённого и выключенного экрана. По умолчанию 3 мин и 10 мин.
- **Внеочередные проверки:**
  - смена сети (`NetworkCallback`);
  - включение экрана;
  - выход из `USER_OFFLINE`;
  - снятие флага портала;
  - перепроверки стабилизатора;
  - кнопка «Проверить сейчас».
- **Автозапуск после перезагрузки** (`BOOT_COMPLETED`), если мониторинг был включён.

### 8.1. Движок проверок отдельно от сервиса

- **`CheckRunner`** выполняет один полный цикл: предварительная оценка, проверки, классификатор, стабилизатор, уведомления. Он не знает, кто его запустил.
- **Носитель** — отдельная абстракция.
  - Сейчас (`fdroid`, `github`): постоянный FGS `specialUse`.
  - На вырост, для `play` или как «экономный режим» во всех сборках:
    - точный будильник поднимает короткий сеанс на один цикл — на 34+ FGS типа `shortService` (до ~3 мин), на 24–33 обычный FGS;
    - события сети приходят через `registerNetworkCallback` с `PendingIntent`.
  - Чем платит экономный режим: нет мгновенной реакции на включение экрана (`SCREEN_ON` нельзя ловить без живого процесса), система ограничивает частоту будильников в Doze, нет постоянного уведомления со статусом.

## 9. Пользовательский интерфейс

Одно Activity, вызывается главным ярлыком.

### 9.1. Главный экран

- Текущий статус, тип сети, время последней проверки, кнопка «Проверить сейчас».
- Состояние каждого VLESS-входа (по метке).
- Счётчик трафика.
- Переход к журналу.

### 9.2. Настройки

- Тумблер мониторинга.
- Интервалы проверки для включённого и выключенного экрана.
- Тумблер «Отслеживать физическое пропадание сети» с подписью.
- Роли приложений: главный VPN-клиент, клиент olcRTC, клиент I2P. Одно приложение может выполнять несколько ролей. Выбор — через свой диалог со списком установленных приложений, с иконками и поиском.
- Редакторы списков 1–4 и ЛК (§2), в списке 1 и ЛК — кнопка Минцифры для каждой записи (§2.3).
- Тема оформления: системная, светлая, тёмная.
- На 24–25: звук и вибрация для каждого типа уведомлений.

### 9.3. Выдача разрешений

При включении мониторинга запрашиваются по очереди, перед каждым — экран с объяснением:
1. уведомления (33+);
2. исключение из оптимизации батареи;
3. точные будильники (31+).

### 9.4. Журнал

Локальный кольцевой буфер на 200 записей: каждая проверка — время, тип сети, статус, трафик и коды результата по каждому ресурсу. VLESS-входы — по названию, без названия — `host:port`. Есть кнопка очистки.

## 10. Хранение и приватность

- Настройки хранятся в DataStore. Последнее состояние — последняя запись журнала (§9.4): общий источник для UI, уведомления сервиса и будущего виджета. После перезапуска приложения она показывается как текущий статус, если ей не больше двух самых длинных интервалов проверки; иначе — «Проверок не было».
- `android:allowBackup="false"`, бэкап данных отключён.
- Сырые vless-ссылки, UUID и ключи нигде не сохраняются и не логируются.
- Сертификаты Минцифры — DER-файлы в `noBackupFilesDir`. В DataStore — только отпечаток и дата загрузки.
- Аналитики и сборщиков падений нет.

- Настройка «Чувствительность» антиспама.
- Тумблер «Строгая проверка VLESS»: `OK_UNVERIFIED` считается недоступным.

## 12. Отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| WorkManager | минимальный интервал 15 минут |
| FGS `dataSync` | лимит 6 ч/сутки на Android 15+ |
| libcurl через NDK | сложная сборка под все ABI без выигрыша перед OkHttp+Conscrypt |
| Cronet (Play Services) | закрытая зависимость от GMS, несовместима с F-Droid |
| Cronet (встроенный) | большой размер, F-Droid не соберёт из исходников; подмена SNI только через экспериментальную `HostResolverRules` на весь движок; движок хранит пулы, кэш и состояние QUIC; слабый контроль таймаутов. Для списка 3 эталон — uTLS, а не Chrome. |
| Google Play на старте | KYC-деанон разработчика; путь на вырост — §1.3 |
| Глобальная галочка Минцифры на весь список | слишком широкое доверие; заменена флагом для отдельной записи (§2.3) |
| minSdk 26 | экономит лишь немного кода совместимости ценой −0,8% мирового охвата (в РФ вероятно больше) |
| Флаг `VALIDATED` как признак связи | Android проверяет связь через gstatic.com, который недоступен в режиме белых списков |
| TUN или VPN как признак утечки | VPN-клиент может пустить трафик из TUN напрямую по правилу для пакета |
| Строка «трафик Cellprobe идёт через VPN» | следить за настройками пользователя — не наше дело; достаточно предупреждения про исключения и того, что наблюдается при проверках |
